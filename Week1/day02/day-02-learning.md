---

## 1. Message Roles

LLM-based applications commonly use three important message roles:

### System

The **system message** defines the overall behavior, rules, personality, and instructions that the AI should follow.

Example:

```text
You are a helpful Java programming tutor.
Explain concepts using simple examples.
```

The system role is one of the most powerful tools for controlling model behavior.

### User

The **user message** contains the actual request or question.

Example:

```text
Explain inheritance in Java.
```

### Assistant

The **assistant message** represents the response generated by the AI.

Example:

```text
Inheritance allows a class to acquire properties and methods from another class.
```

### Message Flow

```text
System → Defines behavior
   ↓
User → Provides task
   ↓
Assistant → Generates response
```

---

## 2. Why the System Role Matters

The same user question can produce completely different responses depending on the system prompt.

For example, the user asks:

```text
Explain Docker.
```

### System Prompt 1

```text
You are a beginner-friendly teacher.
Explain concepts using simple language and real-world examples.
```

The response will focus on simplicity.

### System Prompt 2

```text
You are a senior DevOps engineer.
Give technically detailed explanations and production considerations.
```

The response will be much more technical.

### System Prompt 3

```text
You are an interviewer.
Explain the topic and then ask interview questions.
```

The response will be structured around interview preparation.

### Key Learning

> The user question can remain exactly the same while changing the system prompt can significantly change the model's behavior.

---

## 3. Temperature

**Temperature** controls the randomness and variation in model outputs.

A lower temperature generally produces more predictable responses, while a higher temperature allows more variation and creativity.

### Temperature 0

Best for tasks requiring consistency and predictability.

Examples:

- Code generation
- Data extraction
- Classification
- Structured output
- Repeated production workflows

```text
Temperature: 0
```

The model should generally produce more consistent responses.

---

### Temperature 0.7

A good balanced setting for general-purpose applications.

Examples:

- Chatbots
- Explanations
- General assistants
- Educational applications

```text
Temperature: 0.7
```

Provides a balance between consistency and variation.

---

### Temperature 1.5

Useful for highly creative tasks where variation is desirable.

Examples:

- Brainstorming
- Creative writing
- Story ideas
- Marketing ideas
- Generating multiple creative approaches

```text
Temperature: 1.5
```

Higher temperature can produce more diverse outputs, but may also reduce consistency.

---

## 4. System Prompt + Temperature

A production AI application can combine the **system role** with an appropriate **temperature**.

Example:

```text
System:
You are a professional Java coding assistant.
Always provide correct, concise, production-ready code.
Do not invent APIs.
```

With:

```text
Temperature: 0
```

This configuration is suitable for a coding-focused application where reliability and consistency are important.

For a creative assistant:

```text
System:
You are a creative brainstorming assistant.
Generate unique ideas and explore multiple approaches.
```

With:

```text
Temperature: 1.5
```

This allows more creative variation.

---

## 5. Production-Flavored Thinking

When building an AI application, the prompt and model configuration should match the application's purpose.

| Application | System Prompt | Temperature |
|---|---|---:|
| Code Generator | Strict coding assistant | 0 |
| Data Extraction | Structured extraction assistant | 0 |
| Customer Support | Helpful support agent | 0.2–0.5 |
| Educational Assistant | Friendly teacher | ~0.7 |
| Brainstorming Tool | Creative idea generator | 1.0+ |
| Creative Writing | Creative writer | Higher |

The exact behavior depends on the model and API, so temperature should be tested rather than treated as a universal formula.

---

## 6. Key Takeaways

### Message Roles

```text
System → Controls behavior
User → Gives the task
Assistant → Produces the response
```

### System Role

The system prompt is a major lever for controlling an LLM's behavior.

### Temperature

```text
Low temperature  → More predictable
Medium temperature → Balanced
High temperature → More variation
```

### Production Principle

> Choose the system instructions and model settings based on the application's requirements.

A production coding assistant should prioritize consistency and correctness, while a brainstorming assistant can prioritize creativity and diversity.
